# Первый рабочий этап: технический результат

Дата: 2026-10-25. Unity 6000.3.19f1. Изменения экономики, магазин, удвоение дохода и дополнительное время не добавлялись: владелец выбрал сначала обсудить экономику.

Холодный локальный запуск на новом origin: **5 165 мс** до маркера готовности меню; меню проверено визуально. Это loopback без ограничения сети, не оценка публичного хостинга или мобильного устройства. Цель initial download <30 000 000 байт **не выполнена** уже до Bridge.

В BuildReport особенно велики текстуры персонажей и UI: пять изображений персонажей занимают примерно по 11,27 МБ packed size, затем идут composition guide, изображение для титров, dialogue bubble и текстуры окружения. Это размеры включённых ассетов из отчёта, не отдельные сетевые transferSize; конкретные пути и размеры находятся в JSON.

Отчёты и копии:

- `Reports/Publishing/BaselineDXT/build-report.json.buildreport` — нативный BuildReport Unity.
- `Reports/Publishing/BaselineDXT/file-sizes.json` и `browser-measurement.json` — файловые и браузерные измерения.

- Билды и ZIP находятся в игнорируемом `Builds/`; в Git их добавлять не требуется.

Контрольные скрипты восстановлены из исходной ревизии `5eb18f0` для DXT-замера. SDK в этот момент уже установлен, но не используется исходными скриптами, шаблоном или runtime: Playgama отсутствовал среди ManagedStripped, а распакованные wasm и framework имеют те же SHA-256, что до установки SDK. Gzip-контейнеры могут различаться служебными заголовками. После замера интеграционные скрипты возвращены. Во время работы владелец создал коммит `1ce6a22`; его изменения пакетов и настроек сохранены.

## Интеграция

- UPM: `com.playgama.bridge` 2.3.0, commit `7bb1a42f1840f822f999d81e8c021da6e32b8a8d`. Установка выполнена Package Manager. Используется официальный Bridge template; он инициализирует JavaScript SDK перед Unity. Штатный шаблон загружает CDN `v2/stable` с локальным fallback; UPM commit фиксирован, содержимое CDN может обновляться.
- Bootstrap ждёт асинхронной загрузки сохранений перед переходом в меню. `GameReady` отправляется при загрузке меню; события игрового процесса связаны с состоянием смены и эффективной паузой.
- GameManager объединяет причины паузы: Manual, Platform, Advertisement, Focus, Application, Visibility. Снятие одной причины не снимает остальные. Завершённая смена остаётся замороженной. Перетаскивание отменяется при блокировке игрового ввода.
- Громкости игрока хранятся отдельно от mute платформы. Platform mute и паузы управляют AudioListener, не переписывая настройки игрока.
- Bridge storage: документ версии 1, громкости, отметка прохождения обучения и лучшие чаевые/число завершённых заказов. Настройки пишутся с задержкой 0,6 секунды; одновременные записи сериализованы. Ошибка чтения, некорректная или неизвестная версия блокируют перезапись документа. Незавершённая смена не сохраняется; отметка обучения пока не скрывает существующий туториал автоматически.
- Interstitial запрашивается при прямом переходе из результатов к новой смене. Закрытие/ошибка продолжают переход; повторные запросы во время рекламы блокируются. Ограничения частоты остаются у SDK.
- Для rewarded подготовлены запрос и обработка подтверждения, закрытия и ошибки. Повторное подтверждение не создаёт повторный callback. Продуктовой кнопки и игровой награды пока нет: они зависят от решения об экономике.

## Проверено

Компиляция интеграции без ошибок. В Editor прошли 10 проверок независимых пауз, звука и заморозки результатов; дополнительно проверены дублирующиеся rewarded-события и ошибка SDK.

Браузерный тест выполнен на WebGL Development/Generic-билде с настоящим адаптером Bridge `qa_tool`. Локальный драйвер публичного QA postMessage-протокола симулирует рекламные ответы. Проверены:

- инициализация Bridge и обычного `mock`, и `qa_tool`;
- сохранение платформенной паузы после ручного Resume;
- rewarded: подтверждение один раз, закрытие без подтверждения, ошибка, сохранение ручной паузы;
- interstitial: запрос на результатах, пауза на время показа, продолжение новой смены после Closed и Failed;
- восстановление громкостей после reload через реальные игровые слайдеры и сохранение отметки обучения;
- сохранение документа версии 999 без перезаписи при завершении тестовой смены. Изолированное тестовое хранилище возвращено к исходному отсутствию данных.

Подробности: `Reports/Publishing/BridgeTest/editor-checks.json`, `browser-checks.json`, `build-report.json`. Тестовый Development-билд не является финальным release и не подходит для оценки прироста размера от SDK.

В браузере остаются существовавшие предупреждения: не назначен tutorialBodyText, два PauseSettingsBinder, запрос длины ещё не загруженного аудио. Адаптивность интерфейса и слои туториала/паузы требуют дальнейшей полировки из Publishing_Backlog.

## Повторение локальной проверки

```powershell
node Tools/Publishing/serve.cjs Builds/PublishingBridgeTest 8085
```

Открыть `http://127.0.0.1:8085/?publishingTest=1&localQa=1&platform_id=qa_tool`. Кнопки QA симулируют только ответы SDK и находятся во вставляемом сервером тестовом UI, которого нет в файлах игры. Для проверки неизвестной версии использовать отдельный origin: QA future save → reload → проверить сохранение → QA restore save → reload. Методы диагностики Unity работают только в Editor и на `http://127.0.0.1:`.

Следующий release собирать через активный профиль, например вызовом `PublishingBuild.Queue("Builds/PublishingRelease", "Reports/Publishing/Release/build-report.json", false)` в Editor, чтобы не потерять DXT-subtarget.
