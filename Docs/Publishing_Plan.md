# Crunchie Munchie: подготовка к Playgama

Обновлено: 2026-10-25. Этот план задаёт новую цель после game jam; старые ограничения «itch.io / без сохранений» больше не являются требованиями к публикации.

## Цели

Подробные замечания по UI, звуку, геймплею, арту, онбордингу и мобильному управлению: [Publishing_Backlog.md](Publishing_Backlog.md). Исходное управление «только мышь» из MVP заменено целью поддержки мыши и touch в браузерах iOS/Android.

- Initial download строго меньше 30 000 000 байт. До уточнения методики Playgama измерять холодную загрузку до готовности игры в браузере, включая SDK и обязательные ресурсы. Отдельно фиксировать размер архива, сетевой transfer size и распакованный размер.
- Playgama Bridge: хранение, события паузы и звука, реклама, определение языка, сообщения готовности и игрового процесса.
- Полная английская версия по умолчанию; русская версия сохраняется. Неподдерживаемый язык платформы должен давать английский fallback.
- Рабочий публичный sandbox и проверка метрик; заявка в основной каталог — отдельный этап, без гарантии принятия.

## Подтверждённое состояние

- Unity 6000.3.19f1, URP; CLI 1.0.0-beta.14 и Pipeline 0.9.1-exp.1 доступны.
- Playgama Bridge отсутствует в Packages/manifest.json; Playgama MCP отсутствует среди доступных инструментов текущего чата.
- GameSettings хранит громкости в PlayerPrefs, сохранение вызывает при изменении ползунка.
- GameManager напрямую управляет Time.timeScale. Нужно согласовать ручную паузу, паузу платформы и рекламную паузу.
- SaveSlotSelectionController для Continue вызывает тот же StartGame, что и New Game: это не подтверждение существующего сохранения прогресса.
- TutorialUI и ResultsUI содержат русские строки в коде; необходимо также проверить OrderDataAsset, сцены, префабы и текст на изображениях.
- По архивному чату ранее настраивались WebGL, Mobile URP и лёгкий postprocessing. Фактический текущий initial download не измерен.
- Есть крупные исходные текстуры и музыка в Resources. Размер исходника не равен вкладу в билд; оптимизация должна опираться на BuildReport и импортеры.
- До начала работ уже изменены TMP fallback font, Packages/manifest.json и packages-lock.json. Сохранять эти изменения.

## Порядок работ и критерии приёмки

1. Базовый release WebGL build и отчёт: активный build profile, сцены, настройки, размер data/wasm/framework, крупнейшие включённые ассеты, холодный старт. Сохранить исходные показатели и восстановимую копию затрагиваемых настроек.
2. Интеграция Bridge с зафиксированной версией SDK и его WebGL template. Инициализация должна завершаться до обращения к API. Проверить поведение в Editor и на платформе.
3. Пауза и звук: учитывать независимые причины блокировки. Закрытие рекламы не должно снимать ручную паузу; разрешение звука платформой не должно отменять mute игрока. При скрытии вкладки остановить таймеры, ввод и звук.
4. Хранение через Bridge: версионированная модель, асинхронная загрузка, ошибки и отсутствие данных, отложенная запись настроек. Начальная область сохранений: настройки, завершение обучения, лучшие результаты. Возобновление незавершённой смены требует отдельного игрового решения.
5. Локализация EN/RU: ключи для UI, обучения, заказов, результатов и динамических строк. Язык получать из Bridge, неизвестный — EN; выбранный вручную язык хранить через Bridge. Сам SDK определяет язык, переводы хранятся в игре. Проверить шрифт, переносы и изображения с текстом.
6. Реклама: interstitial в естественном перерыве между сменами. Rewarded только за понятную добровольную награду; награда выдаётся ровно один раз по подтверждению SDK, без неё при закрытии или ошибке. Конкретную награду определить при полировке игрового цикла.
7. Оптимизация итогового билда с SDK и переводами: импорт текстур/аудио, реально включённые Resources, шрифты, шейдеры, stripping и код. Повторный замер холодной загрузки; цель <30 MB подтверждается измерением.
8. Проверка полного цикла: меню → обучение → все заказы → результаты → повтор; потеря фокуса, реклама, mute, перезагрузка, ошибки сохранения и обе локали. Затем список оставшихся проблем полировки по серьёзности.
9. Подключить Playgama MCP и авторизовать кабинет в браузере. Загрузить проверенный билд, подтвердить обнаружение Bridge, получить sandbox URL и проверить события/метрики. Основной каталог подавать после отдельной оценки качества и требований кабинета.
