# Раздел 7.1: Первый melee враг — фундамент (EnemyData + EnemyBase + EnemyStats)

---

## 0. Теория и темы раздела

В этом разделе мы делаем “первого врага” целиком, но **в простом контуре**: конфиг → префаб → базовое поведение.
По смыслу это продолжение того же подхода, что уже был у игрока и оружия:

- `PlayerData` хранит **базовые числа** игрока (макс. здоровье, скорость и т.п.).
- `WeaponData` хранит **базовые числа** оружия (урон, скорость атаки, дальность).
- Теперь **EnemyData** хранит базовые числа **врага** (скорости/дальности/урон/порог обнаружения) и ссылку на его префаб.

Дальше эти данные читает `EnemyBase` (поведение) и `EnemyStats` (адаптер/точка совместимости со “внешними” системами).

**Ключевые идеи:**

- **Разделение данных и логики** (как с `PlayerData`/`PlayerStats` и `WeaponData`/`WeaponBase`).
- **Переиспользование** одного `EnemyData` для создания множества одинаковых врагов.
- **Префаб как “шаблон тела”**, а `EnemyData` как “паспорт с числами”.

В этом разделе мы показываем только то, что нужно для первого рабочего врага:
- `EnemyData`
- `EnemyStats`
- префаб врага
- `EnemyBase`
- базовое преследование игрока
- простая melee-атака (без разбора боевой модели урона/смерти — это следующий раздел)

---

## 1. Цели раздела

- **Техническая цель**: собрать первого melee врага:
  - создать `EnemyData` для него;
  - собрать префаб врага с `EnemyBase` + `EnemyStats`;
  - подключить данные врагу;
  - добиться, чтобы враг “видел” игрока, подходил и атаковал.
- **Обучающая цель**: понять связи “конфиг → префаб → компонент поведения” и научиться дебажить поведение через инспекторные параметры (`DetectionRange`, `AttackRange`, `MoveSpeed`, `attackCooldown`).

После выполнения раздела у тебя будет минимальный результат:

- **один ассет** `EnemyData` (например, `Enemy_Goblin_Default`);
- **один префаб** врага (например, `Enemy_Base_Melee`);
- **один рабочий враг на сцене**: он находит игрока, преследует и делает melee-атаку по дистанции.

Позже это станет базой для:
- второго врага и простого спавна;
- encounter/wave;
- навигации через NavMeshAgent;
- боевой модели урона/смерти (следующий раздел).

## 3. Создание скрипта EnemyData

### 3.1. Шаги в Unity

1. В окне `Project` перейди в папку `Assets/_Scripts/Enemies/`.
2. ПКМ → `Create` → `C# Script`.
3. Назови скрипт **`EnemyData`** (точно так же, как имя класса).
4. Дважды кликни по скрипту, чтобы открыть его в редакторе.

### 3.2. Что нужно сделать в коде

По умолчанию Unity создаст класс, наследующийся от `MonoBehaviour`. Нам нужно:

1. Изменить наследование с `MonoBehaviour` на `ScriptableObject`.
2. Добавить атрибут `[CreateAssetMenu]`, чтобы можно было создавать `EnemyData` через меню `Create`.
3. Добавить публичные поля с понятными атрибутами (`[Header]`, `[Tooltip]`, `[Min]`).

Ниже пример итогового кода. Используй его как ориентир, но набирай код **самостоятельно**, понимая каждую строку.

```csharp
using UnityEngine;

/// <summary>
/// Данные для врага (здоровье, скорость, урон и т.п.).
/// Используется EnemyFactory для создания врагов и EnemyBase для чтения параметров.
/// </summary>
[CreateAssetMenu(
    fileName = "EnemyData",
    menuName = "Game Data/Enemy Data",
    order = 0)]
public class EnemyData : ScriptableObject
{
    public enum EnemyType
    {
        Melee,   // Ближний бой (гоблины, орки)
        Ranged,  // Дальний бой (лучники, маги)
        Boss     // Боссы (особые враги)
    }

    [Header("Общее")]
    [Tooltip("Читаемое название врага (для UI и логирования).")]
    public string enemyName = "New Enemy";

    [Tooltip("Тип врага (ближний, дальний, босс).")]
    public EnemyType enemyType = EnemyType.Melee;

    [Header("Характеристики")]
    [Min(1f)]
    [Tooltip("Максимальное здоровье врага.")]
    public float maxHealth = 50f;

    [Min(0f)]
    [Tooltip("Скорость движения врага (единиц в секунду).")]
    public float moveSpeed = 3f;

    [Min(0f)]
    [Tooltip("Урон, который враг наносит за одну атаку.")]
    public float damage = 10f;

    [Header("Бой")]
    [Min(0f)]
    [Tooltip("Дальность атаки врага (радиус ближнего боя или дальность выстрела).")]
    public float attackRange = 2f;

    [Min(0f)]
    [Tooltip("Дальность обнаружения игрока (на каком расстоянии враг начинает преследовать).")]
    public float detectionRange = 10f;

    [Header("Награды")]
    [Min(0f)]
    [Tooltip("Опыт, который получает игрок за убийство этого врага.")]
    public float experienceReward = 10f;

    [Header("Префаб")]
    [Tooltip("Префаб врага, который будет использоваться для создания экземпляров.")]
    public GameObject prefab;
}
```

Разбор ключевых моментов:

- `EnemyType` помогает отличать типы врагов в других системах (ИИ, анимации, спавн).
- `maxHealth` — максимальное здоровье, которое будет использоваться при создании врага.
- `moveSpeed` — скорость движения врага (единиц в секунду).
- `damage` — урон за одну атаку (будет использоваться в боевой системе на Этапе 8).
- `attackRange` — дальность атаки (для ближнего боя — радиус, для дальнего — дальность выстрела).
- `detectionRange` — дальность обнаружения игрока (для ИИ на Этапе 9).
- `experienceReward` — опыт за убийство (для системы прогрессии игрока).
- Поле `prefab` нужно для `EnemyFactory` — фабрика будет создавать врагов из этого префаба.

## 5. Как EnemyData будет использоваться дальше

На следующих уроках Этапа 7:

- `EnemyStats` будет хранить ссылку на `EnemyData` и:
  - использовать `maxHealth` для инициализации текущего здоровья;
  - использовать `damage` при расчёте урона;
  - использовать `experienceReward` при смерти врага.
- `EnemyBase` будет использовать компонент `EnemyStats`, чтобы:
  - брать `moveSpeed` для движения;
  - брать `attackRange` и `detectionRange` для логики ИИ (подход к цели/атака);
  - не хранить числа напрямую, а опираться на статы.
- `EnemyFactory` будет:
  - принимать `EnemyData` как параметр;
  - создавать экземпляр `prefab` из данных;
  - настраивать на созданном объекте компоненты `EnemyStats` и `EnemyBase`.
- `EnemySpawner` будет:
  - хранить список `EnemyData`;
  - случайно выбирать тип врага для спавна;
  - передавать данные в `EnemyFactory`.

Так же, как и с `PlayerData` и `WeaponData`, ты сможешь:

- создавать разные варианты одного врага (например, `Enemy_Goblin_Weak`, `Enemy_Goblin_Strong`) без изменения кода;
- настраивать баланс через Inspector, а не через переписывание скриптов.

### ООП‑принципы в этом уроке

В этом уроке мы продолжаем применять знакомые тебе принципы ООП:

- **Принцип единой ответственности (SRP)** — `EnemyData` отвечает только за **данные врага** (здоровье, урон, скорость и т.п.), а логика поведения и состояния находится в других классах (`EnemyStats`, `EnemyBase`, ИИ, спавнер).  
- **Разделение данных и логики** — как и в `PlayerData`/`PlayerStats` и `WeaponData`/`WeaponBase`, мы храним числа отдельно от кода, чтобы:
  - переиспользовать один и тот же `EnemyData` для множества врагов;
  - настраивать баланс через Inspector, не переписывая скрипты.

## 7. Как всё связано в коде (короткая карта)

В этом project-срезе враг собирается из 3 частей:

1. `EnemyData` (ScriptableObject) хранит конфигурацию врага.
2. `EnemyBase` (компонент на префабе) читает `EnemyData` и делает runtime-логику: преследование цели и простую melee-атаку.
3. `EnemyStats` (компонент на префабе) — это “адаптер” между `EnemyBase` и системами, которым нужен удобный доступ к смерти/наградам.

Базовый сценарий в связке выглядит так:

- `SimpleEnemySpawner` берёт `EnemyData.enemyData.prefab`, делает `Instantiate` в точку спавна.
- На созданном объекте `SimpleEnemySpawner` вызывает `EnemyStats.Setup(enemyData)`.
- `EnemyStats.Setup()` прокидывает данные дальше в `EnemyBase.Setup(data)`.
- `EnemyBase.Setup(data)`:
  - сохраняет `enemyData`;
  - сбрасывает `currentHealth` на `enemyData.maxHealth`;
  - отмечает, что враг ещё не мёртв.
- `EnemyBase.Start()` (если `autoResolveTargetOnStart = true`) один раз ищет игрока в сцене (`PlayerController`) и запоминает `target`.
- `EnemyBase.Update()` каждые кадр проверяет расстояние до цели:
  - если цель далеко (больше `DetectionRange`) — враг молчит;
  - если цель в радиусе атаки (меньше/равно `AttackRange`) — враг атакует с кулдауном;
  - иначе — враг движется к цели.

Отдельно у компонента есть “событийный выход” для будущей боевой логики (не разбираем в этом разделе глубоко):
- `EnemyBase` имеет событие `OnDied` как точку расширения;
- `EnemyStats` пробрасывает событие наружу в формате `OnDied(EnemyStats)` (так удобнее подписывать награды/спавнер/пул).

## 8. Что важно понять в `EnemyBase` (поведение врага)

Открой `Assets/_Scripts/Enemies/EnemyBase.cs` и посмотри на ключевые поля/свойства:

- `enemyData` — ссылка на `EnemyData` (отсюда берутся числа).
- `target` — текущая цель (обычно игрок).
- `autoResolveTargetOnStart` — если включён, враг в `Start()` попробует **сам** найти игрока (через `PlayerController`) и выставить `target`.
- `attackCooldown` — минимальная пауза между атаками.

Ключевые свойства — это “геттеры” к `EnemyData`:
- `MoveSpeed`
- `DetectionRange`
- `AttackRange`
- `Damage`

Важно: в этом разделе `Damage` нужен **только как число для демонстрации атаки**, а боевую модель урона/смерти мы рассматриваем в следующем разделе.

---

## 9. Что важно понять в `EnemyStats` (адаптер/совместимость)

Открой `Assets/_Scripts/Enemies/EnemyStats.cs`.

В этом репозитории `EnemyStats` — это **адаптер** над `EnemyBase`:
- он хранит ссылку `enemyBase`;
- отдаёт наружу те же числа (`MoveSpeed`, `AttackRange`, `DetectionRange` и т.п.), но через удобный API;
- пробрасывает событие смерти наружу в формате `OnDied(EnemyStats)`.

Почему это нормально для учебного проекта:
- `EnemyBase` — “источник истины” по runtime-состоянию врага;
- `EnemyStats` нужен, чтобы другие системы могли работать с единым ожиданием “у врага есть Stats-компонент”.

## 10. Собираем префаб первого melee врага

### 10.1 Что создать в Unity

1. Создай префаб врага (например, `Enemy_Base_Melee`):
   - В сцене: создай GameObject `Enemy_Base_Melee`.
   - Добавь компоненты:
     - `EnemyBase`
     - `EnemyStats`
   - Добавь collider (например `CapsuleCollider`), чтобы объект был корректным в сцене (для melee это не обязательно прямо сейчас, но будет полезно дальше).
   - Добавь визуальную “болванку” (можно куб/сферу) в дочернем объекте.
2. Преврати этот GameObject в Prefab (перетащи/создай ассет в папке `Assets/_Prefabs/Enemies/`).
3. Удали из сцены оригинальный GameObject (оставь префаб).

### 10.2 Настройка `EnemyBase` (важное для chase/attack)

Открой `EnemyBase` на префабе и проверь:

- `autoResolveTargetOnStart` — включён (true).
  - Тогда врагу не нужно вручную выставлять `target`: он найдёт `PlayerController` сам.
- `attackCooldown` — оставь дефолт (на старте).
  - Это защита от атаки “каждый кадр”.

Для этого раздела есть два корректных пути подключения данных:

**Путь A (самый простой, без спавнера):**
- назначь `EnemyData` прямо в поле `enemyData` у компонента `EnemyBase` на префабе.

**Путь B (через будущую систему спавна):**
- данные будут передаваться через `EnemyStats.Setup()` при создании врага (это больше про следующий раздел со спавном/encounter).

### 10.3 Настройка `EnemyStats`

У `EnemyStats` в инспекторе обычно нет критических ручных полей для простого урока:

- он в `Awake()` подтянет `EnemyBase` на том же объекте;
- а `Setup(enemyData)` (который вызовет спавнер) прокинет данные в `EnemyBase`.

## 11. Подключаем EnemyData к первому врагу (и отключаем урон в рамках 7.1)

1. Открой ассет `Enemy_Goblin_Default` (или тот, который ты выбрал как первый melee).

3. Заполни поле `prefab`:
   - `prefab` → назначь префаб первого melee (`Enemy_Base_Melee`).

## 12. Размещаем врага на сцене и проверяем: “видит → подходит → атакует”

### 12.1 Самый простой тест без спавнера (рекомендуется для 7.1)

1. Перетащи префаб `Enemy_Base_Melee` на сцену (создай один экземпляр).
2. В Inspector у этого экземпляра в `EnemyBase` назначь:
   - `enemyData` → `Enemy_Goblin_Default` (если ты выбрал Путь A)
   - `autoResolveTargetOnStart = true`
3. Поставь врага на расстоянии **меньше `DetectionRange`** от игрока.

### 12.2 Запусти и смотри поведение

При запуске:

- `EnemyBase` найдёт `PlayerController` и начнёт преследовать;
- когда враг подойдёт ближе, чем `AttackRange`, он начнёт melee-атаку с паузой `attackCooldown`.

Что именно нужно проверить в рамках 7.1:

- что атака срабатывает не “каждый кадр”, а с паузой `attackCooldown`;
- что враг реально выполняет переходы `chase -> attack`:
  - когда дистанция меньше `AttackRange` — атака;
  - когда дистанция больше — движение к цели.

Важно: детали нанесения урона и “смерть врага/игрока” будут разбираться на уроке 7.2.

## 13. Что НЕ делаем в этом разделе (scope control)

В этом уроке мы намеренно не трогаем продвинутые темы:

- pooling/factory как обязательный advanced-путь (здесь используем simple-спавнер);
- patrol/wander и сложные state machine-классы.

Твоя задача — получить работающего melee врага с базовым chase/attack и убедиться, что атака запускается по условиям дистанции и кулдауну.
