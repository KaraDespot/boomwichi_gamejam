# Урок 7.2: Урон через IDamageable, урон в обе стороны и смерть

---

## 0. Что изменилось относительно предыдущего состояния и зачем

На прошлых этапах у нас уже были:

- оружие игрока (ближнее и/или дальнее);
- базовый враг с преследованием и атакой;
- статы игрока.

В этом уроке мы делаем **боевое ядро полноценным**: урон проходит **в обе стороны**, и у обеих сторон появляется понятная “смерть”.

### 0.1. Добавили общий контракт `IDamageable`

**Зачем:** чтобы урон наносился не “конкретному классу” (`EnemyBase`, `PlayerStats`), а **любому объекту**, который умеет получать урон.

Это даёт:

- меньше жёстких связей между оружием/врагами/игроком;
- проще расширять проект (новые враги, разрушаемые объекты);
- проще объяснять: “хочешь получать урон — реализуй интерфейс”.

### 0.2. Урон теперь в обе стороны

- **Игрок → враг**: оружие игрока (`MeleeWeapon`, `Projectile`) находит `IDamageable` у цели и вызывает `TakeDamage(float damage)`.
- **Враг → игрок**: враг в `EnemyBase.Attack()` наносит урон своей цели через `IDamageable`.

### 0.3. Смерть врага и игрока

- **Игрок**: `PlayerStats` выставляет `IsDead` и вызывает `OnDeath` один раз.
- **Враг**: `EnemyBase` выставляет `IsDead` и вызывает `OnDied` один раз.

### 0.4. Довели поведение до “замкнутого цикла” (важно для завершения урока)

В этом репозитории в последнем наборе правок зафиксированы важные guard-правила, чтобы бой не “жевал” мёртвые цели:

- **Враг прекращает бой, если цель мертва**: в `EnemyBase.Update()` враг проверяет `IDamageable.IsDead` у цели и не преследует/не атакует, если игрок уже умер.
- **Враг не наносит урон мёртвой цели**: в `EnemyBase.Attack()` перед `TakeDamage` есть проверка `!IsDead`.

Это не “польша”, а минимальная защита от странного поведения (когда враг продолжает наносить урон по нулевому HP).

### 0.5. Правила урока (важно)

- **Вся модель урона — через `float damage`.**
- **Не вводим `DamageInfo` / `DamageContext`.**
- **Враги бьют только игрока.**
- **Игрок бьёт только врагов.**

> Анимации будут позже. Сейчас “удар” — это **логический вызов `TakeDamage`** (по кулдауну/событию), без синхронизации с клипом. Синхронизацию через `Animation Event` вынесем в отдельный урок.

## 1. Теория: почему интерфейс важен для боёвки

Если оружие наносит урон “в лоб” через `EnemyBase`/`EnemyStats`, появляются проблемы:

- дальняя атака не сможет бить другие цели без переписывания кода;
- придётся писать цепочки `GetComponent<EnemyBase>()`, `GetComponent<BossEnemy>()`, `GetComponent<...>()`;
- при рефакторинге врагов легко ломается боёвка.

**Интерфейс `IDamageable`** — это договор:

- оружие не знает, “кто ты” (игрок/враг/объект);
- оружие знает только “умеешь ли ты получать урон”.

## 2. Из чего состоит система и связи компонентов

### 2.1. Контракт урона

`IDamageable` задаёт минимальный API:

- `bool IsDead { get; }`
- `void TakeDamage(float damage)`

### 2.2. Игрок

`PlayerStats : MonoBehaviour, IDamageable`

- хранит runtime-состояние: `currentHealth`, `isDead`;
- при уроне вызывает `OnHealthChanged(current, max)`;
- при смерти один раз вызывает `OnDeath()`.

### 2.3. Враг

`EnemyBase : MonoBehaviour, IDamageable`

- хранит runtime-состояние: `currentHealth`, `isDead`;
- читает баланс из `EnemyData` (maxHealth, damage, ranges…);
- имеет цель `target` (обычно игрок);
- атакует по кулдауну: `TryAttack()` → `Attack()` → `target.TakeDamage(Damage)`;
- при смерти один раз вызывает `OnDied()`.

> В этом репозитории `EnemyStats` используется как **адаптер совместимости** для систем, которые исторически ожидают `EnemyStats`.  
> Но “боевой контракт” для урона — именно `IDamageable` (оружие и атака врага вызывают `TakeDamage(float)`).

### 2.4. Оружие игрока

#### Ближнее (`MeleeWeapon`)

- делает `Physics.OverlapSphere(...)`;
- **находит `IDamageable`** у найденных коллайдеров;
- наносит `TakeDamage(Damage)`.

Ключевой момент этапа: **оружие не должно бить “всё подряд”** — это обеспечивается настройкой `LayerMask`.

#### Снаряд (`Projectile`)

- при `OnTriggerEnter` проверяет попадание по маске;
- находит `IDamageable` и наносит `TakeDamage(damage)`;
- уничтожается.

## 3. Пошаговая часть (Editor + код)

### 3.1. Код: базовая проверка файлов

Убедитесь, что в проекте есть:

- `Assets/_Scripts/Core/IDamageable.cs`
- `Assets/_Scripts/Player/PlayerStats.cs` (реализует `IDamageable`)
- `Assets/_Scripts/Enemies/EnemyBase.cs` (реализует `IDamageable`)
- `Assets/_Scripts/Weapons/MeleeWeapon.cs` (наносит урон через `IDamageable`)
- `Assets/_Scripts/Weapons/Projectile.cs` (наносит урон через `IDamageable`)

### 3.2. Editor: слои и маски (чтобы “игрок бьёт только врагов”)

1. Откройте `Project Settings` → `Tags and Layers`.
2. Добавьте слои:
   - `Player`
   - `Enemy`
3. Назначьте слой `Enemy` на префабы/объекты врагов (важно: на коллайдеры, которые получают попадание).
4. Настройте `LayerMask`:
   - у `MeleeWeapon` поле `Hit Layers` должно включать **только `Enemy`**;
   - у `Projectile` поле `Hit Layers` должно включать **только `Enemy`**.

Это и есть техническое обеспечение правила “игрок бьёт только врагов”.

### 3.3. Editor: префабы врагов (поля EnemyBase должны соответствовать текущему скрипту)

Проверьте на префабах врагов (`DefaultSpider`, `RedSpider` и т.п.), что в компоненте `EnemyBase`:

- включено `Auto Resolve Target On Start` (если вы используете учебный авто-поиск цели);
- выставлены параметры смерти:
  - `Destroy On Death` (для simple-ветки обычно `true`);
  - `Destroy Delay After Death` (например, `0.15`).

Если на префабе остались старые поля вроде `playerTag`/`targetSearchInterval`, значит префаб был создан под старую версию `EnemyBase` и требует пересборки/обновления.

### 3.4. Editor: коллайдеры и trigger для `Projectile`

Чтобы `OnTriggerEnter` гарантированно срабатывал:

- у коллайдера снаряда включите `Is Trigger`;
- убедитесь, что столкновение вообще возможно: **для триггеров чаще всего нужен `Rigidbody` хотя бы на одной стороне контакта** (на снаряде или на цели).

Дополнительный практический чек для этого репозитория:

- на префабе `Projectile` коллайдер и `Rigidbody` удобно держать **на корневом объекте `Projectile`** (а не на визуальном дочернем меше), чтобы попадания стабильно приходили в `Projectile.OnTriggerEnter`.

### 3.5. Враг: цель и правило “враг бьёт только игрока”

`EnemyBase` наносит урон **только своей цели `target`**.

Варианты установки цели:

- авто-поиск цели на старте (учебное упрощение). В текущем коде враг ищет `PlayerController` и берёт его `Transform`;
- установка цели при спавне (предпочтительно для encounter/волновой системы): `enemy.SetTarget(playerTransform)`.

Правило этапа: враг **не должен** наносить урон “по всем вокруг” через оверлап — иначе он начнёт бить союзников/декор/не того игрока.

### 3.6. (Teacher repo) Сцена как демонстрация результата

В `GameScene` в teacher repo обычно держим хотя бы один “учебный” экземпляр врага (например, `Lesson1_DefaultSpider`), чтобы:

- быстро проверить урон/смерть без спавнера;
- визуально убедиться, что у врага правильный слой (`Enemy`) и корректные значения здоровья.

## 4. Частые ошибки (минимально, но обязательно)

### 4.1. Двойная смерть

**Симптом:** `OnDeath` / `OnDied` срабатывает дважды, награда/удаление выполняется дважды.

**Правило защиты:** проверка `isDead` и ранний `return` в `TakeDamage`/`Die`.

### 4.2. Null при Disable/Enable

**Симптом:** после выключения/включения объекта события продолжают вызываться или появляются ошибки.

**Правило:** подписки делаем в `OnEnable`, отписки — в `OnDisable`.

### 4.3. Слои/маски настроены неправильно

**Симптомы:**

- игрок бьёт себя;
- игрок бьёт декорации;
- игрок не бьёт врагов вовсе.

**Решение:** перепроверьте `LayerMask` в `MeleeWeapon`/`Projectile` и слой на коллайдерах врага.

### 4.4. Collider/Trigger

**Симптом:** `Projectile` “пролетает насквозь”, `OnTriggerEnter` не вызывается.

**Чек:**

- `Is Trigger = true` у коллайдера снаряда;
- корректное наличие `Rigidbody` на одной стороне;
- слой цели входит в `Hit Layers`.
