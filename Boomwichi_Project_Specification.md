# Boomwichi: спецификация проекта

## 1. Общая информация

Рабочее название: Boomwichi.

Жанр: казуальный 3D-симулятор готовки с элементами тайм-менеджмента и хаоса.

Референс по базовому циклу: Good Pizza, Great Pizza.

Ключевое отличие: игрок готовит сендвичи в грязной кухне, где продукты могут быть с плесенью, а по столу бегают тараканы.

Платформа: WebGL, desktop browser.

Публикация: itch.io.

Движок: Unity 6.3.

Render Pipeline: URP.

Управление: только мышь.

Объем MVP: 1 игровой день, 3 заказа.

Сохранения: нет.

Вид: 3D, фиксированная камера сверху на рабочий стол.

## 2. Цель MVP

Сделать короткий, законченный и играбельный WebGL-прототип, где игрок:

- получает заказ от клиента;
- собирает сендвич из ингредиентов;
- очищает плесень с продуктов;
- давит тараканов;
- жарит верхний хлеб в грильнице;
- сдает заказ в пакет;
- получает оценку и чаевые;
- проходит 1 игровой день;
- видит финальную статистику.

Главная цель MVP: доказать, что core loop работает и доставляет напряжение через грязь, время и тараканов.

## 3. Игровая фантазия

Игрок работает в сомнительной сендвичной. Клиенты хотят простые заказы, но кухня разваливается: продукты плесневеют, тараканы лезут к еде, хлеб можно пережарить, а заказ больше нельзя переспросить.

Игра должна ощущаться как быстрый, смешной и немного мерзкий low-poly симулятор.

## 4. Scope MVP

В MVP входит:

- главное меню;
- настройки громкости;
- credits;
- туториал перед началом дня;
- один игровой день;
- три последовательных заказа;
- drag-and-drop ингредиентов;
- сборка сендвича на доске;
- грильница для верхнего хлеба;
- плесень на ингредиентах;
- очистка плесени тряской мыши;
- падение плесени на сендвич при ошибке;
- тараканы, бегущие к еде;
- заражение еды тараканом;
- убийство тараканов кликом;
- мусорка для сброса текущего сендвича;
- пакет для сдачи заказа;
- проверка заказа;
- чаевые;
- финальная статистика;
- WebGL-билд для itch.io.

В MVP не входит:

- полноценное перемещение персонажа;
- NPC pathfinding;
- сложные диалоги;
- сохранение прогресса;

- физическая нарезка ингредиентов;
- реалистичная физика еды;
- надкусы от тараканов;
- мобильное управление;
- дополнительные игровые дни.

## 5. Core loop

1. Клиент показывает заказ.
2. Игрок запоминает заказ.
3. Игрок кладет нижний хлеб на доску.
4. Игрок добавляет нужные ингредиенты.
5. Игрок очищает плесневые ингредиенты до добавления.
6. Игрок давит тараканов, пока они не заразили еду.
7. Игрок жарит верхний хлеб в грильнице.
8. Игрок кладет верхний хлеб на сендвич.
9. Игрок перетаскивает сендвич в пакет.
10. Игра проверяет заказ.
11. Клиент реагирует и начисляет чаевые.
12. Начинается следующий заказ.

## 6. Управление

Игрок использует только мышь.

Основные действия:

- ЛКМ по контейнеру: создать ингредиент и сразу начать drag.
- Удержание ЛКМ: переносить ингредиент под курсором.
- Отпустить ЛКМ над валидной зоной: положить объект.
- Отпустить ЛКМ вне валидной зоны: ингредиент исчезает.
- Быстро двигать мышью при удержании плесневого ингредиента: очистить плесень.
- ЛКМ по таракану: раздавить таракана.
- ЛКМ по UI-кнопкам: меню, пауза, настройки.

## 7. Камера и сцена

Камера:

- фиксированная;
- смотрит сверху на стол;
- не вращается;
- не приближается;
- рассчитана на desktop 16:9.

Основные зоны сцены:

- рабочий стол;
- доска для сборки сендвича;
- контейнеры ингредиентов;
- грильница;
- мусорка;
- пакет для выдачи заказа;
- зоны спавна тараканов по краям стола.

## 8. Ингредиенты

Типы ингредиентов:

```csharp
public enum IngredientType
{
    Bread,
    Tomato,
    Cucumber,
    Olive,
    Sauce,
    Cheese,
    Sausage,
    Onion
}
```

Игровые правила:

- хлеб используется как нижний и верхний кусок;
- соус добавляется один раз и не бывает плесневым;
- сыр добавляется одним большим куском;
- овощи и колбаса добавляются по 4 кусочка;
- оливки существуют как возможный ингредиент, но не обязательны для первых трех заказов.

Состояние ингредиента:

```csharp
public class IngredientInstance : MonoBehaviour
{
    public IngredientType Type;
    public bool IsMoldy;
    public bool IsContaminatedByRoach;
    public bool IsPlacedOnSandwich;
}
```

## 9. Хлеб и гриль

Хлеб имеет роль и состояние прожарки.

```csharp
public enum BreadRole
{
    Bottom,
    Top
}

public enum ToastState
{
    Raw,
    Toasted,
    Burnt
}
```

Правила:

- нижний хлеб кладется на доску;
- верхний хлеб перед добавлением должен пройти через грильницу;
- Raw верхний хлеб не принимается;
- Toasted нужен для заказов 1 и 3;
- Burnt нужен для заказа 2.

Грильница:

- принимает только верхний хлеб;
- фиксирует хлеб в точке гриля;
- показывает таймер;
- через 3 секунды переводит хлеб в Toasted;
- через 6 секунд переводит хлеб в Burnt;
- позволяет забрать хлеб после начала готовки.

## 10. Соус

Соус:

- находится в отдельном контейнере;
- берется через drag-and-drop;
- не бывает с плесенью;
- при drop на хлеб спавнит визуальную кляксу;
- записывает в состояние сендвича `HasSauce = true`;
- не должен добавляться больше одного раза.

## 11. Сборка сендвича

Сендвич собирается на доске.

Правила сборки:

- сначала нужен нижний хлеб;
- ингредиенты можно класть только на активный сендвич;
- игра сама укладывает ингредиенты по слоям;
- точные позиции ингредиентов не влияют на проверку;
- после добавления верхнего хлеба сендвич считается закрытым;
- после закрытия нельзя добавлять новые ингредиенты;
- готовый сендвич нужно перетащить в пакет.

Состояние сендвича:

```csharp
public class SandwichState
{
    public bool HasBottomBread;
    public bool HasTopBread;
    public bool HasSauce;
    public bool HasFallenMold;
    public bool HasRoachContamination;
    public ToastState TopBreadToastState;
    public Dictionary<IngredientType, int> IngredientCounts;
}
```

## 12. Мусорка

Мусорка нужна для исправления ошибок.

Правила:

- игрок перетаскивает текущий сендвич в мусорку;
- сбрасывается только текущая собранная еда;
- текущий заказ остается тем же;
- штрафа нет;
- время клиента продолжает идти.

## 13. Пакет

Пакет является зоной сдачи заказа.

Правила:

- игрок перетаскивает закрытый сендвич в пакет;
- после drop запускается проверка заказа;
- если сендвич не закрыт, сдача не происходит;
- после проверки игра показывает реакцию клиента;
- затем начинается следующий заказ или финал дня.

## 14. Заказы

Заказ показывается в облаке текста клиента один раз.

Заказ исчезает:

- после первого действия игрока;
- или после нажатия кнопки подтверждения.

Повторно посмотреть заказ нельзя.

Заказ 1:

- хлеб;
- соус x1;
- колбаса x4;
- верхний хлеб Toasted.

Текст:

> Мне сендвич: соус, колбаса, и хлеб хорошо поджарить. Без лишнего.

Заказ 2:

- хлеб;
- соус x1;
- огурцы x4;
- лук x4;
- сыр x1;
- верхний хлеб Burnt.

Текст:

> Соус, огурцы, лук, сыр. И хлеб пережарь, я люблю почти уголь.

Заказ 3:

- хлеб;
- помидоры x4;
- огурцы x4;
- колбаса x4;
- сыр x1;
- верхний хлеб Toasted.

Текст:

> Без соуса. Помидоры, огурцы, колбаса, сыр.

## 15. Проверка заказа

Проверка запускается после drop сендвича в пакет.

Проверяются:

- наличие нижнего хлеба;
- наличие верхнего хлеба;
- факт прожарки верхнего хлеба;
- нужная прожарка верхнего хлеба;
- наличие нужных ингредиентов;
- количество нужных ингредиентов;
- отсутствие лишних ингредиентов;
- отсутствие плесневых ингредиентов;
- отсутствие упавшей плесени;
- отсутствие заражения тараканом.

Не проверяются:

- точные позиции ингредиентов;
- физический порядок выкладки, если итоговое состояние корректное.

Возможные ошибки:

- MissingIngredient;
- ExtraIngredient;
- WrongIngredientCount;
- MoldyIngredient;
- FallenMold;
- RoachContamination;
- MissingTopBread;
- MissingBottomBread;
- WrongToastState;
- RawTopBread.

## 16. Плесень

Плесень - это:

- визуальные пятна на ингредиенте;
- boolean `IsMoldy`.

Правила:

- соус не бывает с плесенью;
- остальные ингредиенты могут быть плесневыми;
- шанс плесени растет по времени игрового дня;
- максимум шанса к концу дня: 70%.

Формула:

```text
moldChance = Lerp(0.10, 0.70, elapsedDayTime / totalDayTime)
```

Очистка:

- игрок держит плесневый ингредиент;
- быстро двигает мышью туда-сюда;
- растет `shakeProgress`;
- при достижении порога ингредиент очищается;
- спавнятся кусочки/частицы плесени.

Если очистка происходит над сендвичем:

- плесень падает на хлеб;
- `SandwichState.HasFallenMold = true`;
- исправить нельзя, только выбросить сендвич.

Рекомендуемые настройки:

- минимальная скорость движения мыши для shake: настраиваемая;
- время активной очистки: 0.7-1.2 секунды;
- количество частиц плесени: 2-4.

## 17. Тараканы

Тараканы создают хаос и заставляют игрока отвлекаться от сборки.

Правила:

- тараканы спавнятся с первого заказа;
- появляются по краям стола;
- бегут к ближайшей положенной еде;
- максимум одновременно: 3;
- частота спавна растет по мере дня;
- тараканы бегают поверх стола;
- NavMesh не нужен, движение можно делать напрямую к цели.

При касании еды:

- если цель ингредиент: `IsContaminatedByRoach = true`;
- если цель хлеб/сендвич: `SandwichState.HasRoachContamination = true`;
- на цели появляется темное пятно.

Убийство:

- игрок кликает по таракану;
- таракан исчезает;
- появляется временное пятно на 2-4 секунды;
- увеличивается счетчик убитых тараканов.

Надкусы не реализуются в MVP.

## 18. Таймеры

Игровой день:

- длительность: 5 минут.

Ожидание клиента:

- длительность: 90 секунд.

Если таймер клиента закончился:

- заказ провален;
- текущая еда сбрасывается;
- приходит следующий клиент.

Если таймер дня закончился во время заказа:

- игрок может закончить текущий заказ;
- после результата день завершается.

## 19. Чаевые

Чаевые являются оценкой заказа.

Базовая логика:

- идеальный заказ: максимум чаевых;
- одна ошибка состава: штраф;
- несколько ошибок состава: большой штраф;
- плесень или таракан: сильный штраф или 0;
- заказ не успели вовремя: 0.

Точные числа можно настроить после playtest.

Рекомендуемый старт:

```text
baseTips = 10
missingIngredientPenalty = -4
extraIngredientPenalty = -4
wrongCountPenalty = -3
wrongToastPenalty = -5
moldPenalty = -10
roachPenalty = -10
timeoutTips = 0
minTips = 0
```

## 26. Visual style

Стиль: low-poly casual.

Требования:

- форма ингредиентов должна легко читаться сверху;
- плесень должна быть заметной;
- заражение тараканом должно быть заметным темным пятном;
- зоны взаимодействия должны быть понятны без длинных текстов;
- цвета не должны сливаться со столом;
- UI должен быть крупным и читаемым в браузере.

## 27. WebGL требования

URP остается основным render pipeline.

Для WebGL:

- выключить тяжелый post-processing;
- минимизировать realtime shadows;
- использовать простое освещение;
- ограничить количество частиц;
- избегать тяжелых shader graph эффектов;
- проверить Input System в браузере;
- проверить audio unlock;
- проверить размер canvas;
- сделать первый WebGL build в конце первого дня.

itch.io:

- билд должен запускаться в браузере;
- zip должен содержать весь WebGL build;
- на itch.io нужно включить "This file will be played in the browser";
- добавить описание и скриншоты;
- проверить запуск со страницы itch.io.

- красивые частицы;
- разные фразы;
- оливки;
- hover-подсказки;
- дополнительные реакции;
- визуальная полировка.

## 30. Упрощения при нехватке времени

Резать в таком порядке:

1. Оливки.
2. Переход камеры к клиенту.
3. Сложные фразы клиентов.
4. Пятна от раздавленных тараканов.
5. Визуальные кусочки плесени.
6. Settings, кроме volume.
7. Credits.
8. Таймер дня.
9. Грильницу упростить до одной стадии готовности.
10. Тараканов упростить до логики: дошел до сендвича -> сендвич грязный.

Нельзя резать:

- drag-and-drop;
- заказы;
- проверку заказа;
- мусорку;
- сдачу в пакет.

## 31. Основные риски

Drag-and-drop в 3D:

- риск: объект плохо следует за курсором;
- решение: фиксированная камера, одна плоскость стола, крупные drop zones.

Shake detection:

- риск: игроку неприятно чистить плесень;
- решение: мягкий порог и быстрый результат.

Грильница:

- риск: дополнительная система ломает темп;
- решение: одна зона, один таймер, три состояния.

Проверка заказа:

- риск: баги из-за физического расположения;
- решение: проверять структурированное состояние, не позиции.

WebGL:

- риск: поздний билд ломается;
- решение: первый WebGL smoke test в конце первого дня.

## 32. Финальное описание для itch.io

Boomwichi - короткий хаотичный симулятор сендвичной, где вам нужно готовить заказы, стряхивать плесень с продуктов, давить тараканов и не пережарить хлеб. Клиенты ждут недолго, заказ повторять нельзя, а кухня явно давно просится на санитарную проверку.

Управление:

- мышь - взять, перетащить и положить ингредиент;
- быстро двигайте мышью с зажатым ингредиентом, чтобы стряхнуть плесень;
- кликните по таракану, чтобы раздавить его;
- перетащите сендвич в пакет, чтобы отдать заказ.

## 33. Итоговая рекомендация

Для джема важно не количество систем, а цельность. Сначала нужно сделать полный путь: меню -> заказ -> сборка -> сдача -> проверка -> следующий заказ -> финал. После этого добавлять грязь, тараканов, звук и баланс.

Лучший финальный scope:

- 3 заказа;
- 1 игровой день;
- 1 соус;
- без оливок в заказах;
- без смены камеры;
- без сохранений;
- без сложной экономики;
- без надкусов;
- без мобильного управления.
